# Десктопный UI на PySide6

## Когда использовать

- Создание каркаса приложения.
- Добавление экрана, диалога или таблицы.
- Вынос длительной операции в фон.
- Подключение use case к UI.
- Отладка зависаний, утечек и «пустых» таблиц.

## Главное правило

UI — отдельный слой. Он:

- не импортирует `infrastructure`, `sqlite3`, `openpyxl`, `polars`;
- не считает деньги, не парсит Excel, не строит SQL;
- вызывает только application use cases / DTO;
- форматирует данные для отображения.

```text
presentation -> application -> domain
                     ^
              infrastructure (реализует порты)
```

Сборка зависимостей — в `composition.py`, не в виджетах.

### 2. Дашборд

- Верх — шесть KPI-карточек в один ряд: «Выгода шаблонов», «Стоимость», «Сообщений» (подпись — SMS-сегменты), «Доставлено» (процент и «N из M»), «Шаблонов» (подпись — активные/неактивные), «Кандидатов» (все найденные, подпись — «выгодных: N» крупным зелёным, `_candidates_hint`). Карточка «Выгода шаблонов» — текущая месячная выгода после вычета стоимости шаблонов (`total_monthly_net_benefit`), подпись «в месяц, после вычета стоимости шаблонов»; подсказка — `_benefit_tooltip`. Суммы экономии — rich-текст (`_benefit_hint_html`): цвет `positive` темы, 15 px, полужирный.
- Под карточками — строка «Потенциал роста: … ₽ в месяц» и детализация «внедрение кандидатов … · удаление убыточных шаблонов …» (`potential_benefit`, `profitable_candidates_benefit`, `loss_templates_benefit`, use case `GetDashboardSummary`).
- Тулбар: выбор загрузки, переключатель «Обзор / Абоненты» (`QButtonGroup` + `QStackedWidget`) и кнопка «Обновить». «Обзор» укладывается на 1280×820 без прокрутки; `QScrollArea` — запасной вариант для маленьких окон, фон viewport — правило `#dashboardViewport`.
- «Обзор» — две колонки 3:2. Слева «Динамика по дням» (`StackedBarChart` без заголовка: если `title` и `caption` пусты, область заголовка не резервируется) и таблица «Классы сообщений» (строки «Всего / Обычные / Шаблонированные», колонки «Сообщений», «Сегментов», «Счёт», «Средняя стоимость сегмента», «Доля»; в «Доле» — `ShareMeter`). Справа «Структура» адаптивная: в компактном режиме — 100 %-полосы `ShareBarChart` (`widgets/share_bar.py`, `QPainter`) для долей сегментов и расходов и вывод о средней цене сегмента; если правой колонке хватает высоты (FullHD), полосы заменяются двумя `PieChart` «Доли SMS-сегментов» и «Доли расходов». Переключение — `_update_structure_mode` по resize правой колонки, условие — `_structure_pies_fit` с `STRUCTURE_PIE_MIN_HEIGHT`; в расширенном режиме «Структура» растягивается, а операторы фиксируются по содержимому, в компактном — наоборот, поэтому пустоты под таблицей операторов нет. Ниже — «Операторы получателя»: топ-6 + «Другие», колонки «Оператор», «Сообщений», «Сегментов», «Счёт», «Доля» с `ShareMeter`, под таблицей — строка концентрации «Крупнейший — …». Данные — `MessageQueryRepository.operator_statistics`, группировка — `_top_operators`.
- «Абоненты» — второй вид: три карточки («Уникальных абонентов», «Сегментов на абонента», «Сообщений на абонента») и три диаграммы в ряд: `DistributionChart` абонентов по числу сегментов, `PieChart` абонентов по операторам (топ-5, «Другие»), `DistributionChart` сообщений по числу сегментов. Подблоки ряда фиксированы по содержимому (`_sub_block` без `expanding`), круговая диаграмма абонентов поднимается до высоты гистограмм (`AUDIENCE_PIE_MIN_HEIGHT`), поэтому ряд выровнен и не растягивается на весь экран. Группировка — `presentation/desktop/distribution.py` (`group_buckets`), данные — `MessageQueryRepository.segmentation_statistics`, пояснение о допущениях — под блоком.
- Предупреждения — сворачиваемая панель `#warningsCard` внизу, по умолчанию свёрнута; заголовок «▸ Предупреждения и допущения · N», внутри `QPlainTextEdit`.
- Цвета операторов — фиксированная карта `OPERATOR_COLORS` в `presentation/desktop/operator_colors.py`, ключи — значения `Operator`; цвет привязан к оператору, а не к позиции: МТС — красный, Tele2 — чёрный, Megafon — зелёный, Beeline — жёлтый, «Другие» — серый. Шаблонированные SMS в полосах — teal `#0d9488`, обычные — `negative` темы.
- Подзаголовок: файл, период, дата импорта и ошибки отправки/доставки.
- Оформление: карточки на фоне `surface` с тонкой рамкой и скруглением; цвета задаются одним stylesheet страницы (`dashboard_style`), акценты — свойством `tone` у значения. Круговые диаграммы — только для долей целого: расширенная «Структура» и абоненты по операторам; сравнение категорий — горизонтальными полосами и таблицами. Подблоки диаграмм в секции фиксируются по высоте содержимого, растягивается только секция, которой это нужно по режиму.

## Фоновые задачи

Долгие операции — только в `QThreadPool`/`QThread`, не в GUI-потоке.

Во время операции вкладка показывает `BusyOverlay` (`widgets/busy_overlay.py`)
поверх области строк таблицы: полупрозрачный слой с `BusySpinner`
(крутящаяся дуга на QTimer + QPainter, 40 px, цвет акцента темы) в центре
и подписью («Выполняется анализ…», «Пересчёт анализа…», «Идёт поиск
кандидатов…», «Пересчёт кандидатов…»). Слой держится минимум `MIN_VISIBLE_MS`
(450 мс), поэтому виден и при мгновенном ответе из кэша, и не перехватывает
мышь. Паттерн: `_set_busy(True, text)` запускает слой, `_set_busy(False)`
прячет его и останавливает таймер; кнопки и комбобокс загрузки на время
операции блокируются.

Паттерн:

```python
class Worker(QRunnable):
    def __init__(self, fn, *args, **kwargs):
        super().__init__()
        self.fn = fn
        self.args = args
        self.kwargs = kwargs
        self.signals = WorkerSignals()

    def run(self):
        try:
            result = self.fn(*self.args, **self.kwargs)
        except Exception as exc:
            self.signals.error.emit(exc)
        else:
            self.signals.result.emit(result)
        finally:
            self.signals.finished.emit()
```

Правила:

- В worker передавать только DTO/примитивы, не виджеты.
- Результат возвращать в GUI-поток через сигнал.
- Прогресс — отдельный сигнал `(current, total, message)`.
- Отмена — `threading.Event`/флаг, проверяемый в use case.
- Не показывать `QMessageBox` из worker.
- Не трогать виджеты из worker.
- Ошибку показывать человеческим текстом; traceback — в лог.

## Таблицы

- `QAbstractTableModel` + пагинация.
- Модель запрашивает страницу у application use case: `limit`, `offset`, `sort`, `filters`.
- Не грузить 100k строк в `QTableWidget`.
- Для больших таблиц — `QTableView` + `setUniformRowHeights(True)`.
- Форматирование денег/дат — делегаты.
- Сортировка — на стороне SQL, не в модели.
- Булевы значения — `✔` / `✘` из общего форматтера, цвет — `ForegroundRole`
  модели (`QColor`); не выводить «да/нет» словами.
- Связанные таблицы (например, операторы выбранного шаблона) собирать из
  исходной модели по выделению: `currentRowChanged` → `mapToSource` →
  `getattr(item, "template_id")` → чистая функция отбора без Qt.
- Экспорт — отдельный use case, не выгрузка из виджета.
- Excel-отчёт дополнительно содержит лист «Графики» с диаграммами и графиками
  вкладок: доли SMS-сегментов и расходов обычных/шаблонированных SMS,
  сегменты и счёт по операторам (топ-5 + «Другие»), дневные сегменты по
  операторам, распределения абонентов и сообщений по числу сегментов,
  абоненты по операторам, а также дневные ряды «Все/Шаблонированные/Кандидаты»
  для контекста вкладок «Шаблоны» и «Кандидаты». Данные приходят в `ReportBundle`
  из `MessageQueryRepository`; `ExcelReportWriter` строит служебные таблицы и
  `openpyxl`-диаграммы (`BarChart`, `DoughnutChart`), не импортируя Qt и
  presentation.

## Форматирование

- Деньги: `1 234,56 ₽`, `Decimal`, не `float`.
- Даты: `ДД.ММ.ГГГГ`, время `ЧЧ:ММ`.
- Проценты: `12,3%`.
- Телефоны: `79*****1234`.
- Тексты: обрезать в таблице, полностью — в деталях; не логировать.
- Локализация: русский UI, английские идентификаторы.

## Настройки и данные

- Пользовательские данные: `%LOCALAPPDATA%\MtsTemplates`.
- Настройки: `settings.toml` (чтение `tomllib`, запись вручную/через простой writer).
- БД: `mts_templates.db`, WAL.
- Не хранить данные в папке проекта.
- При первом запуске создать каталоги и БД.
- Миграции — версионированные SQL-файлы, применять при старте.

## Ошибки и логирование

- Доменные ошибки → понятный русский текст + код.
- Технические ошибки → «Не удалось выполнить операцию», детали в лог.
- Логи: `%LOCALAPPDATA%\MtsTemplates\logs\app.log`, ротация.
- Никаких телефонов, ФИО и текстов сообщений в логах.
- Не показывать traceback пользователю.
- При падении импорта — откат, данные не должны остаться в полусостоянии.

## Производительность UI

- Запуск окна — без тяжёлого импорта/анализа.
- Первый экран — пустое состояние с подсказкой.
- Импорт/анализ — по кнопке, с прогрессом.
- Кэш агрегатов — в SQLite, не в памяти UI.
- Фильтры — в SQL, не в Python по всем строкам.
- Графики — по агрегатам, не по сырым 100k точкам.
- Закрытие окна во время worker'а — корректно отменять/дожидаться.

## Тестирование

- View models — unit-тесты без Qt, если возможно.
- `pytest-qt` — для сигналов, диалогов, моделей.
- Smoke test: приложение стартует, окно открывается, вкладки переключаются.
- Тест импорта: выбрать fixture, дождаться результата, проверить отчёт.
- Тест ошибки: битый файл → понятное сообщение, без падения.
- Тест отмены: отмена worker'а не оставляет мусор в БД.
