# Десктопный UI на PySide6

## Когда использовать

- Создание каркаса приложения.
- Добавление экрана, диалога или таблицы.
- Вынос длительной операции в фон.
- Подключение use case к UI.
- Отладка зависаний, утечек и «пустых» таблиц.

## Главное правило

UI — отдельный слой. Он:

- не импортирует `infrastructure`, `sqlite3`, `openpyxl`, `polars`;
- не считает деньги, не парсит Excel, не строит SQL;
- вызывает только application use cases / DTO;
- форматирует данные для отображения.

```text
presentation -> application -> domain
                     ^
              infrastructure (реализует порты)
```

Сборка зависимостей — в `composition.py`, не в виджетах.

  «Средняя стоимость сегмента», «Доля (%)»; данные — из

  гистограмма абонентов по числу сегментов, круговая по операторам абонентов,

- Подзаголовок: файл, период, дата импорта и ошибки отправки/доставки.

- Оформление: карточки на светлом фоне с тонкой рамкой и скруглением; цвета

## Фоновые задачи

Долгие операции — только в `QThreadPool`/`QThread`, не в GUI-потоке.

Во время операции вкладка показывает `BusyOverlay` (`widgets/busy_overlay.py`)
поверх области строк таблицы: полупрозрачный слой с `BusySpinner`
(крутящаяся дуга на QTimer + QPainter, 40 px, цвет акцента темы) в центре
и подписью («Выполняется анализ…», «Пересчёт анализа…», «Идёт поиск
кандидатов…», «Пересчёт кандидатов…»). Слой держится минимум `MIN_VISIBLE_MS`
(450 мс), поэтому виден и при мгновенном ответе из кэша, и не перехватывает
мышь. Паттерн: `_set_busy(True, text)` запускает слой, `_set_busy(False)`
прячет его и останавливает таймер; кнопки и комбобокс загрузки на время
операции блокируются.

Паттерн:

```python
class Worker(QRunnable):
    def __init__(self, fn, *args, **kwargs):
        super().__init__()
        self.fn = fn
        self.args = args
        self.kwargs = kwargs
        self.signals = WorkerSignals()

    def run(self):
        try:
            result = self.fn(*self.args, **self.kwargs)
        except Exception as exc:
            self.signals.error.emit(exc)
        else:
            self.signals.result.emit(result)
        finally:
            self.signals.finished.emit()
```

Правила:

- В worker передавать только DTO/примитивы, не виджеты.
- Результат возвращать в GUI-поток через сигнал.
- Прогресс — отдельный сигнал `(current, total, message)`.
- Отмена — `threading.Event`/флаг, проверяемый в use case.
- Не показывать `QMessageBox` из worker.
- Не трогать виджеты из worker.
- Ошибку показывать человеческим текстом; traceback — в лог.

## Таблицы

- `QAbstractTableModel` + пагинация.
- Модель запрашивает страницу у application use case: `limit`, `offset`, `sort`, `filters`.
- Не грузить 100k строк в `QTableWidget`.
- Для больших таблиц — `QTableView` + `setUniformRowHeights(True)`.
- Форматирование денег/дат — делегаты.
- Сортировка — на стороне SQL, не в модели.
- Булевы значения — `✔` / `✘` из общего форматтера, цвет — `ForegroundRole`
  модели (`QColor`); не выводить «да/нет» словами.
- Связанные таблицы (например, операторы выбранного шаблона) собирать из
  исходной модели по выделению: `currentRowChanged` → `mapToSource` →
  `getattr(item, "template_id")` → чистая функция отбора без Qt.
- Экспорт — отдельный use case, не выгрузка из виджета.

## Форматирование

- Деньги: `1 234,56 ₽`, `Decimal`, не `float`.
- Даты: `ДД.ММ.ГГГГ`, время `ЧЧ:ММ`.
- Проценты: `12,3%`.
- Телефоны: `79*****1234`.
- Тексты: обрезать в таблице, полностью — в деталях; не логировать.
- Локализация: русский UI, английские идентификаторы.

## Настройки и данные

- Пользовательские данные: `%LOCALAPPDATA%\MtsTemplates`.
- Настройки: `settings.toml` (чтение `tomllib`, запись вручную/через простой writer).
- БД: `mts_templates.db`, WAL.
- Не хранить данные в папке проекта.
- При первом запуске создать каталоги и БД.
- Миграции — версионированные SQL-файлы, применять при старте.

## Ошибки и логирование

- Доменные ошибки → понятный русский текст + код.
- Технические ошибки → «Не удалось выполнить операцию», детали в лог.
- Логи: `%LOCALAPPDATA%\MtsTemplates\logs\app.log`, ротация.
- Никаких телефонов, ФИО и текстов сообщений в логах.
- Не показывать traceback пользователю.
- При падении импорта — откат, данные не должны остаться в полусостоянии.

## Производительность UI

- Запуск окна — без тяжёлого импорта/анализа.
- Первый экран — пустое состояние с подсказкой.
- Импорт/анализ — по кнопке, с прогрессом.
- Кэш агрегатов — в SQLite, не в памяти UI.
- Фильтры — в SQL, не в Python по всем строкам.
- Графики — по агрегатам, не по сырым 100k точкам.
- Закрытие окна во время worker'а — корректно отменять/дожидаться.

## Тестирование

- View models — unit-тесты без Qt, если возможно.
- `pytest-qt` — для сигналов, диалогов, моделей.
- Smoke test: приложение стартует, окно открывается, вкладки переключаются.
- Тест импорта: выбрать fixture, дождаться результата, проверить отчёт.
- Тест ошибки: битый файл → понятное сообщение, без падения.
- Тест отмены: отмена worker'а не оставляет мусор в БД.
