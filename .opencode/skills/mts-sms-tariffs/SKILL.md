# Тарифные модели МТС-Маркетолога

## Когда использовать

- Реализация или изменение расчёта стоимости SMS.
- Расчёт экономической выгоды шаблона.
- Разбор расхождений между `Стоимость`, `Цена за один сегмент` и прайс-листом.
- Моделирование «а что было бы, если бы сообщение отправили обычным тарифом».

## Базовые понятия

- **Сообщение** — логическая отправка, один `ID сообщения`.
- **Сегмент** — биллинговая единица длины: до 70 символов — 1 сегмент, далее по 67 символов.
- **Обычное SMS** — нешаблонированное, рекламное/произвольное.
- **Шаблонированное SMS** — текст по согласованному шаблону; дешевле, но требует регистрации.
- **Пакет** — предоплаченный объём SMS, действует до конца месяца, остаток сгорает.
- **Подписка** — оплата блоками сообщений одному получателю; не за каждое SMS.
- **Оплата по факту** — фиксированная цена за SMS, только для обычных.
- **Шаблонный сбор** — 2 000 ₽/мес за шаблон при подключённой подписке на шаблонированные SMS.

## Иерархия источников

1. Фактическая `Стоимость` в статистике — истина для уже отправленных сообщений.
2. Фактическая `Цена за один сегмент` в статистике — ставка, применённая МТС.
3. Прайс-лист на дату периода — для прогноза и fallback.
4. Настройки приложения — только если нет ничего выше.

Нельзя пересчитывать фактическую стоимость «по формуле», если она уже есть. Формула нужна для прогноза и для проверки аномалий.

## Выбор модели

| `Тип пакета` в статистике | Класс | Модель |
|---|---|---|
| `Подписка. Все операторы (шаблонированный)` | Шаблонированные | `SubscriptionTariff` |
| `Подписка. Все операторы` | Обычные | `SubscriptionTariff` |
| `Все операторы` | Обычные | `PackageTariff` |
| пусто | Ошибка/нет пакета | не тарифицируется |

Для прогноза обычных SMS модель задаётся настройкой: `package`, `subscription`, `pay_per_message`.

## Пакетный тариф

Алгоритм:

1. Определить объём пакета `package_size` и режим `pricing_mode`:
   - `uniform` — цена за SMS зависит от объёма пакета целиком;
   - `marginal` — tier'ы применяются последовательно к объёму пакета.
2. Для каждого сообщения: `cost = price_per_segment × segments`.
3. Если пакет исчерпан — остаток по overage-ставке оператора.
4. Учесть ограничения:
   - пакет «на всех операторов» подключается не чаще 1 раза в месяц;
   - на MegaFon/Yota — не более 10% SMS пакета, остальное сверх пакета;
   - пакет «на МТС» нельзя использовать для других операторов;
   - остаток неиспользованных SMS сгорает в конце месяца.

Проверка режима:

- В прайсе пример для «Обычные SMS на МТС»: 450 000 SMS = 400 000 × 7,54 + 50 000 × 7,39 — это `marginal`.
- Для «Обычные SMS на всех операторов РФ» пример 1 000 SMS × 9,9 — это `uniform` по объёму пакета.
- Не угадывать: хранить `pricing_mode` в каталоге и сверять с фактическими `Стоимость` из статистики.

## Подписочный тариф

Ключевое: блоки считаются **на получателя**, а не на рассылку и не на кампанию. Нужна последовательность сообщений по номеру за период.

Состояние на получателя:

```text
block_index: 0..N
messages_in_block: 0..20+
charged_blocks: set
```

Правила обычной подписки:

| Сообщения одному получателю | Списание |
|---|---|
| 1–5 | 33 ₽ за блок (при отправке 1-го) |
| 6–20 | 52 ₽ за блок (при отправке 6-го) |
| 21 и далее | 8,5 ₽ за каждое |

Правила шаблонной подписки «на операторов РФ» (МТС, МегаФон, билайн, t2):

| Сообщения одному получателю | Списание |
|---|---|
| 1–5 | 11 ₽ за блок (при отправке 1-го) |
| 6–20 | 35 ₽ за блок (при отправке 6-го) |
| 21 | 15 ₽ |
| 22 и далее | 0 ₽ |

Правила шаблонной подписки «на МТС»:

| Сообщения одному получателю | Списание |
|---|---|
| 1–5 | 7,32 ₽ за блок |
| 6–20 | 28,06 ₽ за блок |
| 21 | 13,42 ₽ |
| 22 и далее | 0 ₽ |

Дополнительно:

- Внутри оплаченного блока `Стоимость = 0`.
- Сброс блоков — на границе месяца и при смене получателя.
- Шаблонный сбор 2 000 ₽/мес за каждый шаблон; списывается в месяц подключения подписки; новый шаблон — сразу; повторное подключение в том же месяце не дублирует списание.
- В фактических данных подписки `Стоимость` многосегментного сообщения часто равна одной ставке блока, а не `ставка × сегменты`. Поэтому:
  - для фактического расчёта использовать `Стоимость`;
  - для симуляции иметь флаг `charge_per_segment`, по умолчанию `false`;
  - включать `true` только если данные периода это подтверждают.

## Оплата по факту

Только обычные SMS. Ставка за сегмент по оператору (прайс 01.11.2026):

| Оператор | ₽/сегмент |
|---|---:|
| МТС | 7,54 |
| МегаФон | 31,90 |
| билайн | 10,35 |
| t2 | 7,10 |
| Прочие РФ | 7,70 |

`cost = rate × segments`. Сверх пакета — те же ставки, если пакет исчерпан.

## Извлечение ставок из статистики

Для исторического периода:

1. Отфильтровать доставленные/отправленные строки с непустой ценой.
2. Сгруппировать по `(Тип пакета, Оператор получателя, Класс сообщения)`.
3. Для пакета: `rate = сумма(Стоимость) / сумма(сегментов)` по строкам с `Стоимость > 0`.
4. Для подписки: взять моду `Цена за один сегмент` среди строк с `Стоимость > 0`; отдельно посчитать долю нулевых списаний.
5. Сравнить с прайсом; если расхождение > 1%, писать предупреждение и использовать observed.
6. Для оператора без обычных сообщений — fallback на прайс и пометка «оценка».

Не включать нулевые списания в среднюю ставку: они искажают её вниз. Нулевые — это отдельная метрика «доля сообщений внутри блока».

## Экономическая выгода

### Активный шаблон

```text
actual = Σ Стоимость(сообщения шаблона) + template_fee × months
baseline = Σ counterfactual_ordinary_cost(те же сообщения)
net = baseline - actual
```

### Неактивный шаблон

```text
actual = template_fee × months
baseline = 0
net = -actual
```

### Кандидат

```text
monthly_saving = (ordinary_cost_per_message - templated_cost_per_message) × monthly_volume
net_monthly = monthly_saving - template_fee
payback_months = template_fee / monthly_saving   (если saving > 0)
```

Требования:

- `Decimal`, округление до копеек только при выводе.
- Указывать период и методику: observed / simulated.
- Для неполного месяца либо считать факт за период, либо явно нормировать на месяц.
- Не сравнивать шаблон с «идеальным» тарифом, который не был доступен в период.

## Тесты

Обязательные границы:

- пакет: 1-й и последний SMS tier'а, переход на следующий tier, исчерпание, overage;
- подписка: 1-е, 5-е, 6-е, 20-е, 21-е, 22-е сообщение одному получателю;
- смена получателя сбрасывает блок;
- смена месяца сбрасывает блок;
- шаблонный fee: 1 и 2 шаблона, неполный месяц, повторное подключение;
- многосегментное сообщение: пакет умножает на сегменты, подписка — по флагу;
- отрицательная и нулевая выгода.

## Частые ошибки

- Умножать ставку подписки на количество сегментов — в фактических данных это часто неверно.
- Считать блоки на рассылку, а не на получателя.
- Забыть шаблонный сбор 2 000 ₽/мес — выгода завышается.
- Брать текущий прайс для октября — исторические ставки другие.
- Считать `Стоимость = 0` ошибкой — это норма внутри блока.
- Смешивать пакет и подписку в одной средней ставке.
- Сравнивать неполный ноябрь с полным октябрём без предупреждения.
