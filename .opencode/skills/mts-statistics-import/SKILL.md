# Импорт статистики МТС-Маркетолога

## Когда использовать

- Добавление или изменение импортёра статистики.
- Проверка новой выгрузки из личного кабинета.
- Расхождение в количестве сообщений, SMS-сегментов или стоимости.
- Подготовка fixtures и тестов для импорта.

## Формат файла

- Один лист, шапка в строке 1, 25 колонок.
- Точные названия и назначение колонок — в `references/statistics-columns.md`.
- Данные приходят в `+03:00`; деньги — числа с плавающей точкой, но в приложении только `Decimal`.
- Файл может быть большим: 100k+ строк, 20+ МБ. Читать потоково.

## Порядок работы

1. **Профилирование.** Запустить скрипт:

   ```bash
   uv run --with openpyxl python .opencode/skills/mts-statistics-import/scripts/profile_statistics.py "doc/statistics/november.xlsx"
   ```

   Для JSON:

   ```bash
   uv run --with openpyxl python .opencode/skills/mts-statistics-import/scripts/profile_statistics.py "doc/statistics/november.xlsx" --json
   ```

2. **Проверить шапку.** Все обязательные колонки на месте, нет сдвига, BOM и лишних пробелов. Названия колонок не угадывать: использовать точное сопоставление с нормализацией.
3. **Проверить период.** Минимум и максимум `Дата попытки отправки`. Если месяц неполный — предупредить пользователя.
4. **Проверить объёмы.** Сверить строки, уникальные `ID сообщения`, сумму `Стоимость`, количество ошибок с ожидаемыми из выгрузки.
5. **Проверить дубликаты.** Один `ID сообщения` может встречаться 2–3 раза с разными биллинговыми компонентами.
6. **Импортировать атомарно.** Ошибка в середине файла — откат всей транзакции, понятное сообщение пользователю.
7. **Показать отчёт импорта.** Строк, уникальных сообщений, период, дубликаты, ошибки, сумма, предупреждения.

## Типы и нормализация

| Поле | Тип | Правило |
|---|---|---|
| `ID сообщения` | str | UUID; ключ логического сообщения |
| `Дата попытки отправки` | datetime | ISO с `+03:00`; хранить timezone-aware |
| `Стоимость` | Decimal | RUB, не `float`; пустое → `None` |
| `Цена за один сегмент` | Decimal | RUB; пустое → `None` |
| `Количество сегментов в sms` | int | пустое/0 допустимо для ошибок |
| `Количество sms в пакете при покупке` | int | `999999999` — сентинел подписки |
| `Текст сообщения` | str | сохранять как есть, не обрезать; не логировать |
| `Номер получателя` | str | нормализовать к цифрам; в UI/логах маскировать |
| `Тип пакета` | str | пустое — ошибка отправки |
| `Статус отправки` | enum | `Отправлено`, `Ошибка отправки` |
| `Статус доставки СМС или ММС` | enum | `Успешная доставка`, `Ошибка доставки`, `Частично доставлено`, пусто |
| `Оператор получателя` | enum | `MTS`, `Tele2`, `Megafon`, `Beeline`, `Other_RF`, `Rostelecom`, `Sbertelecom`, `Smarts_motiv`, `International` |

Неизвестные значения не отбрасывать молча: сохранять исходное значение и писать предупреждение.

## Дедупликация

`ID сообщения` — логическое сообщение. Несколько строк с одним ID — биллинговые компоненты.

Алгоритм:

1. Сгруппировать строки по `ID сообщения`.
2. `Стоимость` сообщения = сумма `Стоимость` всех строк группы.
3. `Количество сегментов` = сумма `Количество сегментов в sms` по строкам группы: длинная SMS оплачивается несколькими частями (например, 23 + 5 + 15 = 43 сегмента). Сумма совпадает с количеством сегментов в ЛК МТС-Маркетолога.
4. Проверить, что в группе совпадают:
   - `Текст сообщения`;
   - `Номер получателя`;
   - `Дата попытки отправки`;
   - `Количество сегментов в sms`.
5. Если метаданные расходятся — не суммировать слепо: пометить группу как `conflict`, показать в отчёте, использовать первую строку для текста/номера.
6. Для количества сообщений считать группу один раз. Для стоимости — сумму всех компонентов.

Пример: одна отправка представлена двумя строками `11 ₽` и `35 ₽`; фактическая стоимость сообщения — `46 ₽`, сообщение — одно.

## Агрегаты

Всегда различать:

- **Строка** — биллинговая запись.
- **Сообщение** — уникальный `ID сообщения`.
- **SMS-сегмент** — биллинговая единица длины.
- **Доставленное сообщение** — есть `Успешная доставка`.
- **Ошибка отправки** — `Статус отправки = Ошибка отправки` или пустой `Тип пакета`.
- **Ошибка доставки** — `Статус доставки = Ошибка доставки`.

Формулы:

```text
messages            = count(distinct message_id)
sms_segments        = sum(segments per unique message)
delivered_messages  = count(distinct message_id with success delivery)
total_cost          = sum(cost per unique message)
effective_cost_seg  = total_cost / sms_segments
```

Если считаешь по строкам, а не по уникальным сообщениям, явно подписывай метрику `rows_*`.

## Известные аномалии

1. **Дубликаты ID.** В октябре 9 254 ID, в ноябре 2 816. Все — с разной стоимостью. Это биллинговые компоненты, а не случайные дубли. У части дубликатов различается количество сегментов (октябрь — 2 887 ID, ноябрь — 461 ID): стоимость и сегменты суммировать, расхождение показывать в отчёте.
2. **Нулевая стоимость.** В подписке сообщение внутри блока стоит 0. Это не ошибка.
3. **Подписка не умножает ставку на сегменты.** Для многосегментных сообщений `Стоимость` может быть равна одной ставке блока. Фактическая `Стоимость` важнее арифметики.
4. **Пустой пакет/цена.** В октябре 538 строк, в ноябре 205. Обычно «Нет подходящего пакета SMS». Исключать из экономики, но показывать.
5. **Ноябрь неполный.** 01–16.11.2026. Не сравнивать абсолютные суммы с полным октябрём без предупреждения.
6. **Ставки меняются.** Октябрьская обычная подписка: 33/42/8 ₽; прайс на 01.11.2026: 33/52/8,5 ₽. Не применять текущий прайс к историческому периоду.
7. **Оператор может быть пустым.** Не падать; fallback и предупреждение.

## Чек-лист импортёра

- [ ] Шапка прочитана и провалидирована.
- [ ] Период определён, неполный месяц помечен.
- [ ] Даты timezone-aware, деньги `Decimal`.
- [ ] Дубликаты схлопнуты по ID, стоимость суммирована.
- [ ] Конфликты метаданных в дубликатах обнаружены.
- [ ] Ошибки отправки/доставки отделены от экономики.
- [ ] `999999999` не используется как размер пакета.
- [ ] Импорт идемпотентен по SHA-256 файла.
- [ ] Есть отчёт: строки, уникальные сообщения, сегменты, сумма, ошибки, дубликаты.
- [ ] Нет PII в логах.

## Частые ошибки

- Считать `Стоимость` как `цена × сегменты` — для подписки неверно.
- Считать строки сообщениями — завышает объём на 5–9%.
- Игнорировать нулевую стоимость — завышает фактические затраты.
- Брать текущий прайс для октября — даёт неверную базу сравнения.
- Загружать все строки в UI — зависание на 100k+.
- Логировать номер или текст целиком — утечка PII.

Ключевые решения, проверенные на реальных выгрузках:

- Excel читается с `infer_schema_length=0`: все значения приходят строками, поэтому
  деньги не проходят через `float`.
- Статусы доставки: `delivered=True` только для `Успешная доставка`;
  `Частично доставлено` считается отдельной метрикой `partial_delivered_rows`.
- Колонки ищутся по нормализованному имени, порядок не важен; отсутствие
  обязательной колонки — `StatisticsImportError` до записи в БД.
- Импорт атомарный: одна транзакция на batch + messages + billing_rows.
