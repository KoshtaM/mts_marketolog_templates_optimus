# Колонки статистики МТС-Маркетолога

Файл: стандартная выгрузка из личного кабинета, один лист, шапка в строке 1.  
Порядок колонок может измениться — сопоставлять по названию, не по индексу.

| # | Колонка | Тип | Обязательна | Назначение и замечания |
|---:|---|---|---|---|
| 1 | `ID сообщения` | UUID | да | Логическое сообщение. Может повторяться в нескольких биллинговых строках. |
| 2 | `ID рассылки` | str | нет | В выгрузках может быть пустым. |
| 3 | `Название рассылки` | str | нет | Обычно пусто при отправке через API. |
| 4 | `Пользователь` | str | нет | ФИО пользователя кабинета. PII. |
| 5 | `Имя отправителя` | str | да | Например, `DOCTORLIGHT`. Ключ для группировки и матчинга. |
| 6 | `Номер получателя` | str | да | Цифры, обычно `7XXXXXXXXXX`. PII; маскировать. |
| 7 | `ФИО получателя` | str | нет | Часто пусто. PII. |
| 8 | `Оператор получателя` | enum | да | `MTS`, `Tele2`, `Megafon`, `Beeline`, `Other_RF`, `Rostelecom`, `Sbertelecom`, `Smarts_motiv`, `International`, пусто. |
| 9 | `Дата попытки отправки` | datetime | да | ISO 8601 с `+03:00`. Ключ периода. |
| 10 | `Статус отправки` | enum | да | `Отправлено`, `Ошибка отправки`. |
| 11 | `Текст сообщения` | str | да | Может содержать переносы строк и эмодзи. PII/содержимое. |
| 12 | `Цена за один сегмент` | decimal | да | Ставка тарифа. Для подписки — ставка блока, не обязательно множитель. Может быть пустой при ошибке. |
| 13 | `Стоимость` | decimal | да | Фактическое списание. Может быть `0` внутри оплаченного блока. Пусто при ошибке. |
| 14 | `Количество сегментов в sms` | int | да | 1 сегмент до 70 символов, далее по 67. Может быть 0 у ошибок. |
| 15 | `Статус доставки СМС или ММС` | enum | да | `Успешная доставка`, `Ошибка доставки`, `Частично доставлено`, пусто. |
| 16 | `Статус доставки в MAX` | enum | нет | Для SMS-анализа не используется. |
| 17 | `Причина неотправки sms` | str | нет | Текст причины; полезен для отчёта об ошибках. |
| 18 | `Причина недоставки sms` | str | нет | Текст причины; полезен для отчёта о доставке. |
| 19 | `Дата и время доставки` | datetime | нет | Может быть пустой. |
| 20 | `Дата подключения пакета` | datetime | нет | Для подписки — дата подключения. |
| 21 | `Тип пакета` | str | да | `Подписка. Все операторы (шаблонированный)`, `Подписка. Все операторы`, `Все операторы`, пусто. |
| 22 | `Количество sms в пакете при покупке` | int | нет | `999999999` — сентинел подписки. Для пакета — объём. |
| 23 | `Канал отправки` | enum | нет | В выгрузках — `API`. |
| 24 | `Переходы по уникальной ссылке` | int | нет | Обычно пусто. |
| 25 | `Канал` | enum | нет | `SMS`, `UNDEFINED`. |

## Наблюдаемые значения

### `Тип пакета`

| Значение | Класс | Модель |
|---|---|---|
| `Подписка. Все операторы (шаблонированный)` | Шаблонированные | Подписка |
| `Подписка. Все операторы` | Обычные | Подписка |
| `Все операторы` | Обычные | Пакет |
| пусто | Ошибка/нет пакета | — |

### `Оператор получателя`

`MTS`, `Tele2`, `Megafon`, `Beeline`, `Other_RF`, `Rostelecom`, `Sbertelecom`, `Smarts_motiv`, `International`, пусто.

Нормализация для расчётов:

- `MTS` → MTS;
- `Megafon` → MegaFon;
- `Beeline` → Beeline;
- `Tele2` → t2;
- `Rostelecom`, `Sbertelecom`, `Smarts_motiv`, `Other_RF` → прочие операторы РФ;
- `International` → международные;
- пусто → неизвестный, fallback.

### `Статус отправки` / `Статус доставки`

Не путать:

- `Отправлено` — сообщение принято шлюзом;
- `Успешная доставка` — доставлено получателю;
- `Ошибка отправки` — не принято;
- `Ошибка доставки` — принято, но не доставлено.

Для активности шаблона достаточно `Отправлено`; для качества и стоимости доставки — `Успешная доставка`.

## Правила чтения

1. Заголовки нормализовать: `strip`, убрать BOM, сжать пробелы, привести к точному виду.
2. Если обязательной колонки нет — остановить импорт с понятной ошибкой, не подставлять `None`.
3. Неизвестные колонки игнорировать, но сохранять в отчёте импорта.
4. Пустые строки пропускать.
5. Числа читать как `Decimal(str(value))`, не как `float`.
6. Даты парсить в timezone-aware `datetime`; если зона отсутствует — считать `+03:00` и предупредить.
7. `999999999` в размере пакета не использовать в расчётах.
8. Стоимость и цена могут быть пустыми — это не ноль, а отсутствие данных.

## Мини-пример дедупликации

Строки:

```text
ID=A, пакет=Подписка. Все операторы (шаблонированный), цена=11, стоимость=0,  сегментов=1
ID=A, пакет=Подписка. Все операторы (шаблонированный), цена=35, стоимость=35, сегментов=1
```

Результат:

```text
сообщений = 1
сегментов = 2
стоимость = 35
```

Если у одной строки стоимость `0`, а у другой `35`, сумма `35` — фактическое списание. Если обе ненулевые, суммировать обе. Сегменты суммируются по строкам: длинная SMS оплачивается несколькими частями.

## Проверки после импорта

- Количество строк и уникальных ID совпадает с ожидаемым.
- Период попадает в заявленный.
- Сумма `Стоимость` совпадает с контрольной суммой файла.
- Доля дубликатов ID в разумных пределах (в известных выгрузках 5–9%).
- Количество строк с пустым пакетом/ценой совпадает с ожидаемым.
- Нет отрицательных стоимостей и сегментов.
- Нет дат вне периода (кроме допустимого лага доставки).
