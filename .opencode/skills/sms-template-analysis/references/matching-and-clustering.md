# Алгоритмы матчинга и сигнатурной группировки

Дополнение к skill `sms-template-analysis`. Здесь — псевдокод и конкретные правила, которые можно переносить в доменный слой.

> Действующие правила: `AGENTS.md`, разделы 9.1 и 11; реализация: `domain/analytics/normalization.py`, `canonical.py`, `csg.py`, `template_syntax.py` и `matching.py`. Сопоставление — только по грамматике МТС, fuzzy не используется.

## 1. Нормализация текста

Реализация — `domain/analytics/normalization.py` с настраиваемой политикой.

```python
def normalize(text: str, policy: NormalizationPolicy) -> str:
    cleaned = unicodedata.normalize("NFKC", text)
    cleaned = INVISIBLE.sub("", cleaned).translate(QUOTES)
    if policy.lowercase:
        cleaned = cleaned.casefold()
    if policy.fold_yo:
        cleaned = cleaned.replace("ё", "е")
    if policy.fold_homoglyphs:
        cleaned = cleaned.translate(HOMOGLYPHS)
    return SPACES.sub(" ", _apply_punctuation(cleaned, policy)).strip()
```

Правила:

- NFKC обязателен: он приводит полноширинные символы и совместимые формы.
- Не удалять цифры: они могут быть частью шаблона.
- Пунктуация: `delete` (по умолчанию), `space` или `keep` — политика общая для кандидатов, грамматики и матчинга.
- Свёртка `ё → е` и омоглифов — только по настройке, по умолчанию выключена.
- Хранить и оригинальный, и нормализованный текст.

## 2. Raw-сущности

URL, e-mail, телефоны и токены, содержащие и цифры, и буквы (`43Б`), становятся
словами-переменными: в шаблоне МТС они превращаются в `%w` (раздел 3).

```python
PATTERNS = [
    ("<URL>", re.compile(r"https?://\S+|www\.\S+")),
    ("<EMAIL>", re.compile(r"\b[\w.+-]+@[\w.-]+\.\w+\b")),
    ("<PHONE>", re.compile(r"\+?\d[\d\s()\-]{9,}\d")),
    ("<DATE>", re.compile(r"\b\d{1,2}[./-]\d{1,2}[./-]\d{2,4}\b")),
    ("<TIME>", re.compile(r"\b\d{1,2}:\d{2}\b")),
    ("<NUM>", re.compile(r"\b\d+(?:[.,]\d+)?\b")),
]

def mask(text: str) -> str:
    text = normalize(text)
    for placeholder, pattern in PATTERNS:
        text = pattern.sub(placeholder, text)
    return text
```

Порядок важен: URL и email до телефона, телефон до числа, дата/время до числа.

## 3. Построение regex из шаблона

Шаблон компилируется по нормализованному тексту с той же политикой
(`compile_pattern` в `template_syntax.py`); переменные — только синтаксис МТС
(`%w`, `%w{1,n}`, `%d`, `%d+`, `%d{1,n}`).

`literal_regex` экранирует текст, пробелы превращает в `\s+`. `variable_regex`:

| Переменная | Регулярка |
|---|---|
| `%w` | `\S+` |
| `%w{1,n}` | `\S+(?:\s+\S+){0,n-1}`, `n ≤ 20` |
| `%d` | `\d+` |
| `%d+` | `\d+(?:\s+\d+)*` |
| `%d{1,n}` | `\d+(?:\s+\d+){0,n-1}` |

При компиляции отклоняются: `%w+`, `%w{1,1}`, `%d{1,1}`, подряд идущие групповые переменные, неизвестные `%x`, шаблон без постоянного текста.

`TemplatePattern.identity` — исходный текст шаблона как есть. Он используется как ключ тождества шаблона при импорте: регистр, пунктуация и пробелы значимы, поэтому две записи с текстами `Ваш код %d` и `ВАШ КОД %d` — два разных шаблона. На сопоставление сообщений это не влияет: там регистр и пунктуация не учитываются.

## 4. Сопоставление

```python
def match_message(text, templates, operator=None):
    normalized = normalize(text)
    hits = [t for t in templates if t.pattern.fullmatch(normalized)]
    if not hits:
        return None
    specificity = lambda t: (t.pattern.literal_length, -t.pattern.variable_count)
    best = max(specificity(t) for t in hits)
    candidates = [t for t in hits if specificity(t) == best]
    if operator is not None:
        for template in candidates:
            if template.applies_to(operator):
                return template
    return candidates[0]
```

Правила:

- Отбор по имени отправителя — до вызова: сравниваются только шаблоны того же отправителя.
- Приоритет: больше литеральных символов, затем меньше переменных.
- При полном равенстве (тексты различаются регистром, пунктуацией или пробелами) выбирается шаблон, в списке операторов которого есть получатель; иначе — первый по `template_id`.
- Оператор получателя на подпадание не влияет; он проверяется отдельно (`applies_to`) и определяет срабатывание.
- Точное совпадение текста — частный случай: шаблон без переменных даёт `literal_length` всего текста.

## 5. Поиск кандидатов (MTS-CSG)

Детерминированная сигнатурная группировка без статистических методов:
реализация — `domain/analytics/normalization.py`, `canonical.py`, `csg.py`.
Нечёткая близость, TF-IDF, embeddings, DBSCAN/HDBSCAN и лемматизация
запрещены как решающий механизм.

```python
def find_candidates(messages, config: CsgConfig):
    normalized = [normalize_for_matching(m.text, config.normalization) for m in messages]
    groups = build_signature_groups(messages, config)   # ключ: (отправитель, сигнатура)
    return extract_candidates(groups, config)           # эмиссия → слияние → линтер → проверки
```

Этапы:

1. **Нормализация** — единая политика (NFKC, нижний регистр, пунктуация
   `delete`/`space`/`keep`, схлопывание пробелов; `fold_yo`, `fold_homoglyphs` —
   только по настройке).
2. **Токенизация** — литеральные слова, числовые серии, raw-сущности
   (URL, e-mail, телефоны, токены с цифрами и буквами) → переменные-слова.
3. **Каноническая сигнатура** — литералы по значениям, числа только по числу
   групп в серии, переменные маркером.
4. **Точная группировка** — ключ `(отправитель, сигнатура)`.
5. **Эмиссия** — числа → `%d`/`%d{1,n}`/`%d+` по наблюдаемым длинам серий,
   переменные → `%w`; литералы печатаются в исходной форме (`surface`):
   регистр, пунктуация и тире сохраняются, при разных написаниях берётся самое
   частое.
6. **Слияние литеральных участков** в `%w`/`%w{1,n}`: кластеры по «скелету»
   (последовательность участков литерал/число/слово) у одного отправителя;
   сохраняются общий префикс, суффикс и якорь внутри участка; хвостовые
   варианты (`… паспорт`, `… паспорт DOCTORLIGHT`) остаются разными
   шаблонами; участок с числом вариантов ≤ `max_literal_cardinality` не
   обобщается.
7. **Линтер** — правила 9.1, плюс две словесные переменные подряд запрещены.
8. **Проверки** — `fullmatch` всех сообщений группы (покрытые целиком группы
   поглощаются) и анти-оверматч `max_foreign_matches` (по умолчанию 0).
9. **Статусы** — `auto_validated`, `needs_human_approval`, `warning_saved`,
   `rejected`.

Порог группы: минимум сообщений `min_support` и минимум SMS-сегментов
`min_cluster_segments`. Слияние всегда даёт статус `needs_human_approval`:
переменную подтверждает человек.

## 7. Экономика

```python
def candidate_economics(group, ordinary_rate, templated_rate, fee, months=1):
    messages = group.unique_messages
    segments = group.segments
    ordinary_cost = ordinary_rate * segments
    templated_cost = templated_rate * segments
    saving = ordinary_cost - templated_cost
    net = saving - fee * months
    payback = fee / (saving / months) if saving > 0 else None
    return Economics(
        ordinary_cost=ordinary_cost,
        templated_cost=templated_cost,
        saving=saving,
        net=net,
        payback_months=payback,
    )
```

Ставки — `Decimal`. Для кандидата использовать observed-ставку шаблонированных сообщений того же оператора/отправителя, иначе прайс.

## 8. Тестовые сценарии

1. **Постоянный текст**: шаблон `Ваш код %d` и сообщение `Ваш код 1234`.
2. **Групповая переменная**: `Запись на %w{1,2} по адресу %w{1,6}` и `Запись на 12.08.2026 17:40 по адресу г. Киров, пер. Гостиный 5/1`.
3. **Пунктуация и регистр**: `ВАШ КОД %d, никому не сообщайте!` совпадает с шаблоном `Ваш код %d никому не сообщайте`.
4. **Ложное срабатывание**: короткий шаблон `Добрый день!` не должен матчить всё; частичное совпадение не считается.
5. **Несколько шаблонов**: побеждает шаблон с большим числом литеральных символов, затем с меньшим числом переменных.
6. **Сигнатурная группа**: 10 сообщений `Запись на 12.08.2026 17:40 по адресу …` с разными адресами → точные группы, объединяемые слиянием в `%w{1,n}`.
7. **Шум**: 3 разных текста → не кандидат (порог поддержки не пройден).
8. **Покрытие**: шаблон обязан покрывать 100% сообщений своей группы (`fullmatch`); иначе отклонение.
9. **PII**: в логах нет телефонов и текстов; в выгрузке — маска.
10. **Детерминизм**: повторный запуск даёт те же группы; случайных seed нет.

## 9. Пороговые значения по умолчанию

| Параметр | Значение |
|---|---:|
| Минимальная длина текста | 20 символов |
| Минимум сообщений в группе (`min_support`) | 5 |
| Минимум SMS-сегментов в группе (`min_cluster_segments`) | 5 |
| Число вариантов литерального участка (`max_literal_cardinality`) | 3 |
| Максимум слов в `%w{1,n}` / `%d{1,n}` | 20 |
| Чужих совпадений допускается (`max_foreign_matches`) | 0 |
| Глубина хвостового якоря слияния (`max_tail_depth`) | 4 |
| Минимальная длина литералов (`min_text_length`) | 8 символов |

Все параметры — в конфиге и в UI настроек. Меняя порог, показывать, сколько групп/сообщений затронуто.
