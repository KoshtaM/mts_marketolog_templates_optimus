Задача проекта:

Этот проект предназначен для оптимизации работы с SMS-шаблонами в работе
через агрегатор SMS-сообщений МТС-Маркетолог.
СМС-шаблоны при отправке сообщений через API необходимы для того, 
чтобы уменьшить стоимость SMS-сообщений.
Чем большее количество сообщений зашаблонировано, тем меньше затрат на отправку SMS.

Проект призван реализовать систему мониторинга статистики СМС-шаблонов, которая
сможет выводить статистику по шаблонам,
в автоматическом режиме выявлять вновь появившиеся незарегистрированные СМС-шаблоны в таблице сообщений.


Ресурс МТС-Маркетолог расположен по этому адресу: https://marketolog.mts.ru
Правила составления СМС-шаблонов описаны здесь: https://support.mts.ru/mts_omnichannel/pravila-soglasovaniya-shablonov-soobschenii/poryadok-soglasovaniya-shablonov-mts?ysclid=mwg9bwv0d635997731
Мы используем его только как СМС-агрегатор для отправки СМС.
Файл с текущими тарифами и видами тарификации находтся в папке /doc в файле prices.pdf
Изучи виды тарификации (пакетная и подписочная) для шаблонированных и обычных СМС
и создай соответствующие модели тарификации. Эти модели потребуются для моделирования
разных видов тарификации. 
В папке /doc/statistics/  расположены таблицы
october.xslx и  november.xslx
со статистикой МТС-Маркетолога за октябрь и ноябрь соответственно.
В октябре обычные сообщения тарифицировались по подписочной модели тарификации,
а в ноябре обычные сообщения тарифицировались по пакетной модели тарификации.
Изучи эти таблицы и сделай соответствующие выводы.




Текущее состояние:
На данный момент статистика по СМС-шаблонам и их экономическая эффективность определяется вручную.
Это приводит  к повышенным трудозатратам и порой к несвоевременному определению неэффективных СМС-шаблонов,
что приводит к лишним тратам на оплату платных СМС-шаблонов.





Исходные данные для обработки:
- Система должна иметь возможность подгрузки Excel-таблицы со статистикой отправки сообщений через МТС-шлюз
 (файл статистики выгружается из личного кабинета МТС-Маркетолог, его формат стандартизирован).
- Система должна иметь возможность подгрузки Excel-таблицы со списком активных СМС-шаблонов
- Весь анализ должен выполняться на основании статистики из этих двух файлов
- Стоимость зарегистрированного СМС-шаблона


Функционал:
На основе исходных данных программа должна предоставить следующую информацию:
- Для активных СМС-шаблонов:
   - Актуален ли шаблон (есть ли хоть одно сообщение с таким шаблоном). Если неактуален, то вероятно, его стоит либо удалить, либо подкорректировать (автопоиск близких по смыслу сообщений)
      И если Актуален , то:
         - процент срабатывания (?)
         - количество сообщений и СМС по этому шаблону
         - экономическая выгода рабочего шаблона в рублях  (разница между тем, сколько было заплачено за СМС, отправленные по этому шаблону (с учётом стоимости зарегистрированного
	   СМС-шаблона)  и тем, в какую сумму обошлась бы отправка этих СМС по текущему тарифу для обычных СМС)

- Автопоиск групп однотипных ещё незашаблонированных сообщений:
  - автогенерация шаблона
  - подсчёт количества сообщений/СМС в группе
  - подсчёт экономической выгоды от шаблонирования этих сообщений

- При моделировании разных видов тарификации для вычисления экономической выгоды при помощи заранее определённых моделей
  тарификации стоимостные харатеристики должны извлекаться из таблицы статистики, выгружаемой из МТС-Маркетолога. 
  Эти данные можно извлечь из статистики отправленных сообщений за период.

Технические требования:

- Язык программирования Python
- пакетный менеджер uv
- использование принципов чистого кода
- Активное применение паттернов проектирования, принципов SOLID, KISS, DRY
- применение приципов чистой архитектуры
- следование принципам DDD (Domain Driven Design)
- бизнес-логика должна быть реализована внутренними слоями
- фронтенд должен быть реализован отдельным слоем и взаимодействовать с бизнес-логикой через интерфейс
- реализация фронтенда как десктопное приложение
